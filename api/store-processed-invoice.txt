POST https://n8n-n8n.qoezvx.easypanel.host/webhook/f/finguard/store-processed-invoice

API Type: POST

Description:
This endpoint stores the complete processing results of an invoice after all validation checks have been completed. It saves the invoice data along with the FULL API RESPONSES from each validation step (OCR, arithmetic accuracy, price anomaly, duplicate detection, GST validation, and GST rate validation).

Request Fields:
- invoice_data (object): Complete extracted invoice information
  - invoice_number (string): Invoice number
  - invoice_date (string): Invoice date
  - invoice_amount (string): Total invoice amount
  - vendor_name (string): Vendor name (if available)
  - vendor_gstin (string): Vendor GSTIN
  - company_gstin (string): Company GSTIN
  - hsn_sac_codes (array): Array of HSN/SAC codes
  - line_items (array): Array of line item objects
  - subtotal (string): Subtotal amount
  - cgst_amount (string): CGST amount
  - sgst_amount (string): SGST amount
  - igst_amount (string|null): IGST amount
  - gst_rate (string): GST rate

- api_responses (object): FULL API RESPONSES from each validation step
  - ocr_processing (object):
    - success (boolean): Whether OCR was successful
    - comments (string|null): Error message if failed
    - full_response (object): Complete OCR API response with all extracted data
  
  - arithmetic_accuracy (object):
    - success (boolean): Whether arithmetic check passed
    - comments (string|null): Details if failed
    - full_response (object): Complete arithmetic validation response including verification details
  
  - price_anomaly_check (object):
    - success (boolean): Whether price anomaly check passed
    - comments (string): Summary message
    - full_response (object): Complete price anomaly API response with benchmark comparisons, deviation percentages, and risk levels
  
  - duplicate_detection (object):
    - success (boolean): Whether duplicate check passed
    - comments (string): Summary message
    - full_response (object): Complete duplicate detection response including matching invoices, similarity scores, and scan details
  
  - gst_validation (object):
    - success (boolean): Whether GST validation passed
    - comments (string|null): Error message if failed
    - full_response (object): Complete GST validation response including vendor and company GSTIN details, legal names, registration status
  
  - gst_rate_validation (object):
    - success (boolean): Whether GST rate validation passed
    - comments (string): Summary message
    - full_response (object): Complete GST rate validation response including HSN/SAC validations, applicable rates, and rate breakdowns

- processing_status (object): Summary status of each validation step (for backward compatibility)
  - ocr_processing (object):
    - success (boolean): Whether OCR was successful
    - comments (string|null): Error message if failed
  - arithmetic_accuracy (object):
    - success (boolean): Whether arithmetic check passed
    - comments (string|null): Details if failed (e.g., "Subtotal mismatch: Expected 160000, Got 159000")
  - price_anomaly_check (object):
    - success (boolean): Whether price anomaly check passed
    - comments (string|null): Details about anomalies found
  - duplicate_detection (object):
    - success (boolean): Whether duplicate check passed (true = no duplicate)
    - comments (string|null): Details if duplicate found
  - gst_validation (object):
    - success (boolean): Whether GST validation passed
    - comments (string|null): Error details if failed
  - gst_rate_validation (object):
    - success (boolean): Whether GST rate validation passed
    - comments (string|null): Details about rate anomalies if found

- overall_status (string): Overall processing status
  - "completed": All validations passed
  - "completed_with_warnings": Completed but some warnings (e.g., price anomalies)
  - "failed": One or more critical validations failed

- processed_at (string): ISO 8601 timestamp of when processing completed
- file_name (string): Original uploaded file name
- file_type (string): File type (pdf, png, jpeg)

Response Format:

Success Response (HTTP 200):
[
  {
    "success": true,
    "invoice_id": "673c5e1f2a8d9b4c6849d123",
    "message": "Invoice processed and stored successfully"
  }
]

Failure Response (HTTP 200):
[
  {
    "success": false,
    "error": "Failed to store invoice data",
    "details": "Database connection error"
  }
]

Error Response (HTTP 400):
{
  "error": "Invalid request body",
  "details": "Missing required field: invoice_data"
}

Response Fields:
- success (boolean): Indicates whether the invoice was stored successfully
- invoice_id (string): Unique identifier assigned to the stored invoice (MongoDB ObjectId)
- message (string): Success message
- error (string): Error message if success is false
- details (string): Additional error details if available

Usage Notes:
1. This endpoint should be called after ALL validation steps are completed
2. It should be called regardless of whether validations passed or failed
3. The processing_status object should accurately reflect the result of each step
4. If a step fails, subsequent steps may not have been executed - mark them with success: false and appropriate comments
5. The invoice_id returned can be used to reference this invoice in other operations (feedback, reports, etc.)
6. Store the complete invoice data for audit trail and reporting purposes

Example Workflow:
1. OCR processing completes → Extract data
2. Run all validation checks (arithmetic, price anomaly, duplicate, GST, GST rate)
3. Collect results from all validation steps
4. Call this endpoint with complete invoice data and all validation results
5. Store the returned invoice_id for future reference
