GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback

Description:
Retrieve all submitted feedback entries for processed invoices. This endpoint returns a list of all feedback submissions with filtering capabilities.

Request Headers:
(No special headers required)

Query Parameters (Optional):
- feedback_type: Filter by issue type (e.g., "ocr_error", "gst_validation_error")
- severity: Filter by severity level (e.g., "critical", "major", "minor")
- invoice_id: Filter by specific invoice ID
- status: Filter by feedback status (e.g., "open", "in_progress", "resolved", "closed")
- submitted_by: Filter by submitter email
- limit: Number of results to return (default: 100)
- offset: Number of results to skip for pagination (default: 0)

Example Requests:

1. Get all feedback:
   GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback

2. Get critical issues only:
   GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback?severity=critical

3. Get OCR errors:
   GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback?feedback_type=ocr_error

4. Get feedback for specific invoice:
   GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback?invoice_id=IN000000000000001

5. Get paginated results:
   GET https://n8n-n8n.j8euv3.easypanel.host/webhook/fetch-feedback?limit=20&offset=0

Field Descriptions:

id (string):
  Unique identifier for the feedback entry (auto-generated)

invoice_id (string):
  ID of the related invoice

invoice_number (string):
  Invoice number from the processed invoice

vendor_name (string):
  Vendor name from the processed invoice

feedback_type (string):
  Type of issue (ocr_error, data_mismatch, gst_validation_error, etc.)

severity (string):
  Severity level (critical, major, minor)

title (string):
  Brief summary of the issue

description (string):
  Detailed description of the issue

expected_result (string, nullable):
  What was expected

actual_result (string, nullable):
  What actually happened

affected_fields (string, nullable):
  Comma-separated list of affected fields

suggested_fix (string, nullable):
  User's suggestion for fixing the issue

status (string):
  Current status of the feedback:
    - "open": Newly submitted, not yet reviewed
    - "in_progress": Being investigated/worked on
    - "resolved": Issue has been fixed
    - "closed": Feedback closed (may or may not be resolved)
    - "duplicate": Marked as duplicate of another feedback
    - "invalid": Not a valid issue

submitted_at (string):
  ISO 8601 timestamp when user submitted the feedback

submitted_by (object):
  User who submitted the feedback
    - name (string): Full name
    - email (string): Email address

created_at (string):
  ISO 8601 timestamp when feedback was created in database

updated_at (string):
  ISO 8601 timestamp of last update

resolution (string, nullable):
  Description of how the issue was resolved (if resolved)

resolved_at (string, nullable):
  ISO 8601 timestamp when issue was resolved

resolved_by (object, nullable):
  User/team who resolved the issue
    - name (string): Full name or team name
    - email (string): Email address

Notes:
- Results are sorted by submitted_at in descending order (newest first)
- All timestamps are in ISO 8601 format (UTC)
- Empty arrays are returned when no feedback matches the criteria
- Pagination is recommended for large datasets
- The status field is managed by administrators/support team
- Resolution details are only populated when status is "resolved"
